# 正文翻译首轮预算和逐段回填

《Deploying Daybreak Red》抓包显示首轮的 294 个输出 token 全部用于推理，正文为零。补译扩大到 588 后返回六段，但同上限重放也曾只返回一段。

## 实现

- 首轮输出额度估算加入推理余量。组批和拆段计入余量，发送时还可使用模型预算中的剩余空间。已配置 `none`、`minimal` 或 `low` 的模型使用其中最低的档位。
- 逐条解析正文增量。每条有效译文单独写入并推送。一个增量包含多条记录时逐条发布，最后一条 JSON 完整时直接提交。超长段仍以全部片段合成为进度单位。
- 缺段告警同时记录输出上限、首个正文增量的时间和结束原因，便于区分预算截断与早期缺少正文。

## 验证

- 使用 Mac 上该文章的缓存副本、临时 SQLite 和用户提供的本地网关运行修复后的正式正文服务。一次请求发送六段，输出上限为 1318，进度事件依次达到 1/6 到 6/6。启用模型配置的 `low` 档位后复测首段约 6.28 秒、第六段约 6.73 秒、终态约 6.79 秒。此前未指定推理档位的一次请求也完整结束，首段约 9.0 秒、终态约 10.43 秒。
- 使用《A support workflow with Grok Bot, Executor and T3 Code》公开正文及本地网关复测。按已配置容量和 `low` 档位发出一笔 89 段请求，输出上限 12282，实际生成 8586 个输出 token，`finish=stop`。约 60.25 秒提交首段，约 81.91 秒提交第 89 段，约 82.87 秒完成。首段前的推理等待仍可见。
- Go 全量测试、`go vet ./...`、翻译和模型层竞态测试、阅读器 42 项组件测试、前端类型检查及改动文件的 ESLint 通过。
- 429 段模拟回归仍可在预算允许时走单次请求，第一条进度为 1/429。同一增量多段、末段缺换行、断流后续译和阅读位置均有回归。
- 本轮桌面界面验证使用阅读器组件测试。
