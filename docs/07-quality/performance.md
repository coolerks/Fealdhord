# 性能目标与实验方法

以下为拟定验收预算，不是测得成绩。基线设备必须记录 CPU／内存／OS／WebView、屏幕刷新率、数据量与 commit。

| 指标 | 初始目标 | 测量方式 |
| --- | --- | --- |
| 100k 文章热全文搜索 | p95≤300ms，中文单字≤800ms | 本机查询端到端 30 次，固定 query fixture，分别记录 Go／UI |
| 应用可交互启动 | 热≤2s、冷≤4s（不含迁移） | 进程启动到首个可操作真实界面，10 次 |
| List⇄Masonry | 输入后≤100ms出现反馈，≤450ms稳定 | 同一结果与锚点，不等待图片网络 |
| 连续滚动／拖动 | 60fps 体验目标，交互期间避免>50ms长任务 | 30 秒 trace，报告 p50／p95帧耗时与长任务 |
| 图片到达锚点误差 | ≤24px | 可见锚点加载前后相对位置 |
| 取消反馈 | UI≤100ms，受控 I/O≤1s开始收尾 | Cancel 到快照／连接取消；外部不可控结果单独标记 |
| DOM 数量 | 随视口／列数／overscan 增长，不随总数线性增长 | 1k／10k／100k 对比挂载条目计数 |
| 媒体缓存 | ≤256MiB，LRU／TTL 生效 | 超预算触发回收，清除后不删文章 |

规模数据为明确标注的合成 fixture，含中文／英文、长文、缺日期、重复 URL、多分类和图片各种比例。记录创建种子与平均正文大小；性能探针不能冒充真实用户研究。冷／热分开，搜索结果正确性先于耗时。

瀑布流测试窗口调整、列数变化、上滚分页、未知图片尺寸、失败重试、滚回视口与 Reader 打开／关闭。滚动时不做全局 layout 动画；内存与 DOM 测量和 Go 数据库检索分别报告。若预算不满足，保留具体失败证据并调整实现或用 ADR 修订，不静默放宽。
