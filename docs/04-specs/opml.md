# OPML 导入导出规格

Phase 4 已接入设置「导入与导出」、macOS 系统文件菜单、Windows／Linux 应用菜单及命令面板。原生文件对话框选择目标；前端只持有能力 token 和文件名，不能提交宿主路径。

## 解析与选择

采用 Go encoding/xml，兼容 OPML 1.0／1.1／2.0，结构以[官方 OPML 2.0 规格](https://2005.opml.org/spec2.html)为依据。最大10MiB、XML结构深32／outline深16、100000个outline、200000个token及10000个唯一Feed；拒绝DTD／外部实体、多根、多body、重复属性和非法XML。解析不联网，不跟随 include／link。

xmlUrl 经 HTTP(S) URL 规范化去重，保留路径和查询大小写；不是将整个 URL 转成小写。同源出现在不同 Folder 只建一个 Feed、多分类关联；空 Folder 保留。声明 RSS 却缺 xmlUrl、非法 URL、Feed下带子项或分类超过5层，预览标记原因并禁选，不静默摊平。非 Feed outline 作为 Folder。预览每页200行，选择跨页保留；选择子项包含祖先，取消Folder选择同步清除后代。

## 两阶段导入

文件能力最多8个、10分钟、一次性且限定用途；私有预览最多4份、10分钟。预览不写库、不刷新，完整计划只保存在Go；前端确认仅提交 preview_id、所选key、是否应用历史文章和是否刷新。可取消预览或在途处理；服务端同时跟踪已消耗token对应的处理，防止取消后遗留不可见预览。

确认消费一次性预览；同一事务复核分类、Feed配置／归档状态／关联摘要，冲突要求重新预览，失败整体回滚。并行刷新检查时间／validator变化不使预览无故过期。复用同父同名分类与源身份；恢复归档源，保留旧自定义名称、阅读状态和手动分类规则；关联只做并集。历史应用关闭时，新增关联仅对后续新文章生效，刷新旧文不补分配。

报告新增／复用／恢复／新增分类／新增关联／跳过数。保存后可选排入刷新，复用现有10000目标有界队列、全局4／每站点2并发；队列失败不回滚已保存的订阅，界面明确提示稍后手动刷新。取消提交可能与数据库提交交错，因此界面要求检查列表后重新预览，不承诺已提交事务回滚。

## 导出与文件提交

导出只含活动订阅及分类树；多分类Feed在对应Folder重复outline，无分类Feed放根级，空Folder保留。仅输出名称、xmlUrl、htmlUrl，不输出密钥、历史、AI配置、内部ID／路径。孤立分类或关联不能静默丢失；超限拒绝并保留目标。

先完整编码，在同目录0600临时文件写入／Sync／关闭，再复核授权目标和目录身份、文件大小与修改时间。已有目标原子Rename；新目标独占硬链接提交，防检查后被其他文件抢占。失败或提交前取消清理临时文件并保留目标；不支持硬链接的文件系统返回安全错误。取消若晚于最终提交，文件可能已保存，应检查目标文件。未宣称断电耐久性或全部平台原生对话框已实机验证。

## 验收

- OPML-01：嵌套、多分类重复、坏URL、空Folder；导出再导入保持源集合和关系；复用／恢复保留自定义名称及历史应用范围。
- OPML-02：XXE／超限／过深被拒；预览零写入；取消中止在途预览；预览冲突／坏项事务回滚；提交前取消及导出失败保留目标。
