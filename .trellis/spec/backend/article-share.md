# 文章手动发送

## 1. 范围

阅读页、列表和瀑布流单篇「发送到」，以及列表工具栏批量发送。点击发送是一次明确的桌面操作。

## 2. 签名

`notification.API.SendArticle(ctx, ArticleShare) error`。单篇传 `article_id`，批量传按列表排序的 `article_ids`。请求同时包含 `channel_ids`、`summary_limit`、`message_limit` 以及布尔选择 `title`、`summary`、`link`、`full_text`、`split_articles`。偏好字段为 `article_share_count` 和 `article_share_summary_limit`，旧偏好读取缺字段时使用默认值 10 和 50。

## 3. 契约

按 ID 从本地库读取文章。选中全文时优先使用匹配文章版本的已提取正文，其次使用订阅正文。仅有摘要时复用 Reader 提取原文。默认将多篇文章合并，勾选 `split_articles` 后每篇另起一条。用 `Message.Links` 的结构化标题、原文链接和文本渲染每篇，复用通知队列对各渠道已验证的收件目标展开。旧队列记录仍按原形状读取。成功响应表示全部入队。

按 Unicode 码点限制单条消息的纯文本内容，包括标题、网址和分隔符。各渠道可采用更严格的 UTF-8 字节或格式限制。优先在完整文章之间拆分，单篇正文太长时按字符拆分，保留初始投递顺序。整篇标题和链接放不下时将标题移入正文分段，网址作为完整链接发送。

批量来源为打开弹窗时当前筛选和排序后的列表前缀。单篇和批量弹窗默认勾选标题、链接和摘要。摘要按 Unicode 码点计数，超过限制时保留指定数量并追加 `…`。文章缺失摘要或链接时，继续发送该篇可用的所选字段。

## 4. 校验与错误

至少选一个内容及渠道，批量最多 50 篇。摘要限制为 1–500 字，未传值时用 50。单条消息字数为 100–2,000，未传值时用 1,500。文章及渠道 ID 均不可重复，入队前校验渠道全部已启用且已验证。原文网址本身超限时保留完整性并提示修改上限或取消链接。某篇文章没有任何可发送的所选内容、全文提取失败或任何目的地不可用时，整次操作不入队。

## 5. 案例

标题和链接在 Telegram HTML、Discord 内嵌链接、Slack 链接、钉钉和企业微信 Markdown、飞书和 Lark 富文本中用标题作链接标签。微信和 QQ 纯文本附网址。仅选链接时以网址为内容。仅选摘要或全文时不补文章标题或链接。

## 6. 回归测试

覆盖阅读菜单、列表项和工具栏，默认条数、设置保存及使用、按列表顺序合并及逐篇发送。验证单条字数上限、渠道字节预算、全文末段保留及无效目标导致零投递。用模拟渠道检查原文地址、链接标签与纯文本回退。

## 7. 错误与正确做法

直接把全文交给适配器会触发消息长度裁剪。先分段入队，再按渠道格式化。禁止用页面传入的正文、URL 或凭据代替文章 ID 和本地数据。
