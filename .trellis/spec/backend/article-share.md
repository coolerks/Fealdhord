# 文章手动发送

## 1. 范围

阅读页和文章列表的「发送到」以及对应通知投递。点击发送是一次明确的桌面操作。

## 2. 签名

`notification.API.SendArticle(ctx, ArticleShare) error`。请求含 `article_id`、`channel_ids` 以及布尔选择 `title`、`summary`、`link`、`full_text`。

## 3. 契约

按 ID 从本地库读取文章。选中全文时优先使用匹配文章版本的已提取正文，其次使用订阅正文。仅有摘要时复用 Reader 提取原文。限制正文片段为每段 500 个字符，第一段携带选中的标题与链接。按段保留初始到期顺序，复用通知队列对各渠道已验证的收件目标展开。成功响应表示全部入队。

## 4. 校验与错误

至少选一个内容及渠道。渠道 ID 不可重复，入队前校验全部已启用且已验证。所选原文链接或摘要不存在、全文提取失败或任何目的地不可用时，返回可读错误，整次操作不入队。

## 5. 案例

标题和链接在 Telegram HTML、Discord 内嵌链接、Slack 链接、钉钉和企业微信 Markdown、飞书和 Lark 富文本中用标题作链接标签。微信和 QQ 纯文本附网址。仅选链接时以网址为内容。仅选摘要或全文时不补文章标题或链接。

## 6. 回归测试

覆盖阅读菜单和列表操作、单选及全选渠道、仅摘要、仅链接、全文跨段及末段保留、无效目标导致零投递。用模拟渠道检查原文地址、链接标签与纯文本回退。

## 7. 错误与正确做法

直接把全文交给适配器会触发消息长度裁剪。先分段入队，再按渠道格式化。禁止用页面传入的正文、URL 或凭据代替文章 ID 和本地数据。
