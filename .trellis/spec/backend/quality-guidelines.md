# 后端质量与验证

状态：已评审代码契约；Phase 0 已有基础工程，涉及其余领域的规则仍待对应阶段实现。

## 1. 范围与触发条件

任何应用 Go 代码变更与交付前。

## 2. 签名

预期命令 `go test ./...`、`go vet ./...`、gofmt 检查；Phase 0 已建立 go.mod，test／vet／race 已实际通过。

## 3. 契约

核心契约写有行为断言的测试，AI 用 httptest，RSS 用合法本地 fixture；禁止测试依赖收费 API。固定生成器，生成输出可复现。

## 4. 校验与错误矩阵

缺测试证据→未验证；构建失败→不可交付；跨平台无 launch 证据→未测。

## 5. 良好、基础和异常案例

良好：多个工具参数交错仍各执行一次；基础：纯文本 Generate；异常：损坏 SSE 不执行未闭合调用。

## 6. 必需测试

遵循 docs/07-quality/testing-strategy.md，涉及网络／数据库／权限时覆盖失败与取消，不写仅镜像实现的测试。

## 7. 错误与正确做法

错误：编译通过即报功能完成。正确：用户路径、相关测试、文档、状态和交接同时更新。

权威详细设计：[架构](../../../docs/03-architecture/overview.md)。

## Phase 0 真实依据

[基础契约](../../../docs/04-specs/bootstrap.md)记录实际服务、DTO、事件合并、测试与生成命令。生成绑定不能手改；早到乱序事件使用同一个 sequence 合并器，类型与构建测试必须采用兼容的 Vite／Vitest 版本。

生成绑定需先保证 go:embed 匹配资源存在；Taskfile bindings 用标准 Node fs 准备忽略的 dist 占位，禁止依赖开发机遗留 dist 才能构建。

macOS调试包更新不能原位cp覆盖已有签名Mach-O。曾出现立即codesign验证失败、随后同文件验证通过的缓存现象；bundle:mac先移除可重建的目标可执行文件，再复制新inode、签名并严格验证。修复后连续两次重打包通过；此行为仅针对bin下构建产物，不清理用户数据，不等于发布签名／公证。
