# Phase 5 技术方案

1. SQLite 保存 Provider、Model、模型分配与会话数据。系统凭据存储只经 Go 访问。更新凭据先写新引用，数据库提交后回收旧引用，失败时补偿。存储不可用时显示可操作错误。
2. Adapter 实现统一 Generate／Stream，协议映射与 SDK 类型留在各 Adapter 内。首项调研对照官方协议与 Mock 结果选择 SDK 或标准 HTTP，并固定版本。客户端只使用保存配置的 origin。路径拼接、受保护请求字段、重定向、取消及响应上限纳入测试。
3. Chat 服务接收用户文本和显式上下文引用。Go 读取有界正文或选段，构造请求并维护操作 ID、事件序号、终态和快照。前端按序合并事件，掉线重取快照。失败、取消和重启后中断保留已写入的部分内容及其状态。
4. 设置和 Chat 沿用现有组件与图标。凭据输入用局部短期状态，提交后清空。历史记录使用模型名称快照，删除配置时提示受影响的分配。
