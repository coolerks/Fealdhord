# Phase 5 · AI 服务与基础 Chat 连续实施计划

本阶段以桌面版可配置、可发送、可停止、可恢复的 Chat 为交付单位。沿用现有父任务和三个子任务。实现过程中按功能边界本地提交，每次提交后继续下一项。阶段验收通过后统一汇报。

## 起点

- Chat Completions 已实现单轮文本、流式工具参数拼接及工具结果续轮，提交为 `30f7311` 和 `2d0424f`。
- SQLite 迁移截至 `00008`。现有全局和文章 AI 入口打开设置页。Provider、模型分配和会话尚未接入。
- 开发以 `docs/05-api/model-contract.md`、`docs/04-specs/providers.md`、`docs/04-specs/chat.md` 和凭据 ADR 为边界。

## 1. 完成三种模型协议

在 `internal/ai` 增加 Responses 与 Messages 实现。共享 HTTP 超时、取消、体积限制和安全错误映射，分别编码各协议的消息、工具和结束事件。Chat Completions 的已有回归继续作为兼容门禁。

- Responses 使用原生输入和输出项。工具结果以 `call_id` 对应原调用。区分完成、失败和不完整响应，保留可用于续轮的协议状态引用。
- Messages 按 content block 索引累积文本和工具参数。工具结果以 `tool_use_id` 放入用户消息。收到 `message_stop` 后才能确认成功终态。
- 每种协议都用本地 HTTP fixture 覆盖普通文本、流式文本、交错工具参数、工具结果续轮、拒绝、用量、未知事件、错误帧、超限、认证、限流、超时、取消和缺失终态。参数未闭合时保留已收到的文本和失败状态。整批调用验证后再发出完成事件。
- 本阶段的桌面 Chat 仅使用文本。模型适配器的工具往返由协议测试验证，实际工具执行归 Runtime。

## 2. 接通服务、凭据与模型设置

- 新增 Provider、Model 和用途分配迁移，从 `00009` 起顺序编号。关联关系在数据库事务中校验。模型保存服务归属、远端模型 ID、显示名和启用状态。五类用途独立分配。
- 按凭据 ADR 实现系统存储和会话内存回退。敏感值只经 Go 写入凭据存储。配置读取仅返回存在状态。更新时先写新凭据，事务提交后回收旧引用。数据库失败回收新引用，清理失败记录脱敏信息。
- 模型工厂根据保存的协议、配置和凭据创建适配器。实现基础 URL 与路径的组合规则，覆盖含或不含 `/v1`、自定义 Header、Query、Extra Body、超时和禁用参数。请求保护字段以适配器为准，按已保存的服务配置发起请求。
- 在 `main.go` 注册 Wails 服务，重新生成前端绑定。设置页可维护多个服务和模型、手填模型、分配用途、显式测试连接。连接测试支持取消，发起前显示可能产生费用的提示。
- 验收覆盖升级旧库、配置重启恢复、凭据更新补偿、服务或模型禁用、删除影响、无模型、取消和错误脱敏。使用测试凭据存储跑自动测试，实机凭据验证按平台记录。

## 3. 交付桌面 Chat 和会话恢复

- 迁移保存会话、消息和生成状态。发送时写入用户消息和助手占位状态。生成中保留有界的部分输出，完成、失败和取消以事务确定终态。启动时将遗留运行状态标记为中断。
- Go 服务按当前会话生成操作 ID 与递增事件序号。同一会话有一条活动生成，查询接口提供可恢复的快照。前端处理重复和失序事件，发现序号缺口后重新读取快照。
- 接通侧栏、分类和文章入口。全局入口只发送用户显式选定的资料。分类入口将候选限制为当前分类的有效成员。文章入口提供当前文章和可移除的选段。发送前显示将使用的模型和上下文，确认时固定请求快照并执行上下文限额。
- Chat 支持发消息、取消、查看历史和重开会话。未配置模型时提供设置入口。消息列表只在用户位于底部时随流滚动。取消和重启后中断均保留部分内容及其状态。
- 用替代模型和临时数据库验证三种入口的上下文差异、并发发送拒绝、序号缺口恢复、取消、失败和重启恢复。组件测试覆盖设置到对话的正常路径及未配置时的阅读行为。

## 4. 整体验收与收尾

1. 使用本地模拟服务串起配置模型、测试连接、发起对话、取消并重开历史。检查实际请求中包含的文章范围与界面所示一致。
2. 运行 Go 测试、vet、相关竞态测试、Wails 绑定生成、前端类型和组件测试、桌面生产构建。真实系统凭据或平台交互的必要实机验证按实际结果记录。
3. 以阶段验收结果同步子任务、CURRENT、路线图和交接。阶段完成后进入 Phase 6 自动分类与精选。Phase 7–8 再接入 Runtime 与工具执行。

当前计划的实现入口是模型适配器任务，紧接着补齐 Responses 与 Messages，再连续推进设置和 Chat。
