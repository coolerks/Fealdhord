# 通知渠道与 AI 定时任务设计评审

2026-11-21。用户已确认折栈运行时发送消息，应用退出后在下次打开时自动补齐。本篇是实现前评审建议。已确认的运行边界与建议默认行为在各节标注。

## 评审结论

Go、本机 SQLite 和应用现有生命周期足以实现。首选独立的 Go 调度与投递服务，使用现有数据库、凭据存储、模型接入和工具权限。渠道、订阅推送规则和 AI 任务各自保存，通过同一投递队列发送。完整交付仍覆盖九个渠道的可用能力，个人微信和 QQ 优先验证主动投递。单一账号的实测成功只证明该账号和目标可用。

## 1. 补齐是两条独立路径

| 情况 | 建议行为 | 验收 |
| --- | --- | --- |
| 已入库、已排队、还未发出 | 启动后继续原投递；按单目标及拆分片段续跑。任务与目标仍然有效才可出队。 | 发送前退出后恢复一次，已成功的目标和片段不重发。 |
| 退出期间源站发文，折栈尚未见过 | 启动触发到期订阅刷新，先恢复本地已有队列，再将刷新发现的新文章纳入恢复批次。只有源站在恢复时仍提供的文章可补齐。 | 模拟退出三天、源站新增与删除、HTTP 错误、部分订阅成功。失败订阅稍后发现的新文章仍有独立入账路径。 |
| 逐条规则积压大量文章 | 正常运行逐条发送。恢复时对积压按目标与格式合并，保留所有匹配文章，按平台限额拆分，记录每篇对应的批次与片段。 | 多分类重复命中只收录一次。恢复批次的文章与逐条记录共享去重键。 |
| 每日汇总错过多个窗口 | 保留原窗口与任务日期。按日期分组，可在一条恢复批次里投递多个窗口；不向接收人发送空摘要。 | 连续错过三天时每个窗口都可查，重复启动结果一致。 |
| AI 任务错过执行 | 一次性提醒恢复后执行一次并标明原定时间。周期 RSS 简报合并错过的窗口。普通周期 AI 任务用最近一次到期计划补跑一次，并在历史显示合并的次数，避免积压生成和重复收费。 | 注入重启、暂停区间、模型取消、产生结果后退出与部分投递成功。 |

关窗口时沿用现有「关闭窗口时」偏好。进程继续在后台时任务继续，彻底退出后恢复。设备休眠期间时钟不会驱动进程，唤醒后使用同一补偿路径。调度进程只负责本机执行。

### 时间窗与分类语义

- 新文章用已有 `upsertArticle` 的新增分支识别。文章窗口默认以首次发现时间归属。配置显式保存时区、收录起止、发送时间。收录窗口采用左闭右开，支持跨午夜，发送时间必须能对应已结束的窗口。DST 缺失时刻顺延到当天第一个有效时刻，重复时刻只运行一次。保存表单预览下一次发送时间和本次窗口。
- 应用恢复时，源站明确且可信的发布时间若落在已知离线区间，可将新发现文章补入它对应的错过窗口。无法可靠定位历史窗口的文章标作「恢复时新发现」，按恢复规则交付。使用归窗时间只决定分组，不改变首次入库身份；同一规则、文章和目标只生成一个可发送条目。已经交付的汇总保留原记录，迟到条目用补充批次。
- 默认不回推首次订阅历史。须覆盖直接添加以及 OPML 和待刷新订阅的首次成功基线，不能单靠 UI 添加调用区分。304、正文更新、改分类和收藏不生成新文章事件。
- 复用 `effective_article_categories`，选中父分类时遵循阅读页相同范围。逐条规则在初次处理时用已有分类匹配；如果后来才有 AI 分类，首次获得匹配可补入尚未发送的逐条规则。每日规则在派发时使用已有有效分类。对同一文章的后续分类变化保留去重键；归档、撤销范围或删除目标时废止尚未外发的项。

## 2. 业务状态与可靠性

首选沿用 SQLite / sqlc 迁移，保留现有 `CommitFeed` 返回值给媒体摄取。在新文章事务内追加轻量事件，投递和图片 IO 在事务外。Go 服务启动时清理中断租约、检查到期任务，再异步唤醒现有 RSS 刷新。应用可以保存这些实体：

| 实体 | 建议最小字段 / 唯一约束 |
| --- | --- |
| 文章事件 | 单调事件序号、文章 ID、订阅 ID、首次发现时间、来源或基线记号。 |
| 渠道连接 | 类型、名称、目的地标识、凭据引用、可用能力、启用状态、版本。Webhook 全链接视为凭据。 |
| 推送规则／任务 | ID、版本、触发规则、时区、数据范围、格式、目标绑定、启停状态、下次执行时间。 |
| 任务运行 | 任务 ID + 原定业务时点作唯一键。保存运行状态和已生成结果，发送失败优先续投递。 |
| 投递记录 | 规则 + 文章 + 目标，或运行 + 目标 + 片段作唯一键。保存待发、执行中、接受、暂时失败、失败、结果未知、取消及可用的外部消息 ID。 |

数据库领取使用原子更新或 CAS，短事务后再请求平台。发送前重新核对任务版本、目标和授权。对 HTTP 429 按平台退避提示处理并有限重试。只有明确没提交或平台支持幂等键才自动重试相应发送。若服务端接受后、客户端确认前退出，标记「结果未知」，尊重已送达风险，保留可审阅的重送入口。平台确认意味着已接受请求，用户实际看见以实机接收验证为准。[SQLite UPSERT](https://www.sqlite.org/lang_upsert.html)

改时间、暂停、恢复或删除需能清楚解释其作用。建议未开始的旧计划作废，已排队记录继续显示原有状态，改目标后旧批次不能转发到新目标。暂停期间不产生待补计划，恢复从新生效时间开始。凭据替换不能借用旧目标的验证结果。一个失败的目的地不影响其他目的地。

## 3. 调度、平台 SDK 和内容技术选型

| 选型 | 结论 | 理由 |
| --- | --- | --- |
| Go `time`、IANA 时区、本地数据库到期扫描 | 首选 | 一次性、每日和指定星期用结构化字段表示。启动、唤醒、配置修改、最近到期触发同一扫描；便于用假时钟穷举恢复行为。 |
| robfig/cron 等表达式库 | 复杂周期再引入解析能力 | 库的内存回调不能保存已发生的运行。其 DST 前跳处理也不等同于本产品的补齐规则。即使引入，使用数据库驱动进度而非依赖回调历史。[robfig/cron 时区](https://pkg.go.dev/github.com/robfig/cron/v3#hdr-Time_zones) [Go time](https://pkg.go.dev/time#Date) |
| 外部消息队列、服务器调度、系统定时项 | 首版无依赖 | 本机应用及 SQLite 已提供所需所有权和恢复边界。额外服务会带来部署和凭据同步成本。 |
| Bot API / Webhook | 纯出站优先官方 HTTP 接口 | Telegram、Discord、Slack、钉钉、飞书、Lark、企业微信群机器人均采用按连接类型的适配器，复用 JSON、限流和审计。复杂鉴权、上传、QQ 或微信长连接优先评估 SDK，锁版本前检查上下文取消、重试与持久化接口。[渠道表](notification-channels.md) |

渠道能力以已配置连接为单位表达，含主动发送、富链接、远程图片、上传、文字长度和返回语义。发送统一内容对象，平台适配器分别生成 Markdown 方言、卡片或纯文本。仅标题也含可点击原文标题或原文 URL；无有效 URL 时仍可发送标题。正文保留原文链接，允许按长度拆分并显示实际发送范围。首图通过现有网络策略取受限图片，优先可用的媒体缓存和平台上传；只支持外链的连接需要可公开读取的 HTTPS 图片。首图关闭时同时关闭支持控制的链接预览。按目标覆盖转义、mentions、签名、403、429 和返回 200 但业务失败。

微信先确认扫码、会话标识、安全存储、无新入站消息情况下隔时发送、跨重启和令牌失效。QQ 分群聊、私聊及频道验证目标授权、频控、无关联入站消息发送与隔时发送。测试消息进入渠道并且明确主动模式后才开启自动规则。平台拒绝时保留可操作状态。 [腾讯微信协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md) [QQ 发送文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md) [腾讯 QQ 插件](https://github.com/tencent-connect/openclaw-qqbot/blob/main/README.zh.md)

## 4. AI 定时任务和通知工具

「自然语言 → 结构化草稿 → 确认卡 → 服务端验证并保存」复用已有聊天和工具权限。确认卡展示实际日历、时区、下一次执行、分类或来源、固定文本或摘要任务、接收目标。支持一次性、每天、指定星期和工作日。工具可查询任务与连接、创建、调整、暂停、恢复、删除，或对已配置目标提出一次明确发送。详细候选见渠道调研。

后台取任务当时的版本和权限，用固定提醒、RSS 查询或范围受控的摘要执行器。摘要走已有 Go 模型接口，限制数据、输入输出和模型预算，可独立于聊天会话运行；原会话只用于展示入口和创建来源。模型输出只作为结果，连接和接收人由已确认的记录决定。后台重跑已保存的生成结果不会再次请求模型。通知工具以保存的连接 ID 寻址；密钥、连接创建、权限变更由设置交互管理。外部内容不参与授权决策。

## 5. 实施顺序与验收

1. 并行验证渠道能力的工程顺序为先取得已授权微信、QQ 测试目标，尽早跑隔时主动发送验证。其余平台用官方 API 合约和专用目标验收。
2. 实现数据库迁移和首次入库事件，先通过新增、更新、首次订阅、重复刷新与事务回滚回归，再加入调度、补齐、摘要窗口和投递状态。
3. 在「通知」接连接、规则、测试发送和投递历史。复用现有 shadcn/ui 表单控件及可搜索多选，用预览核对纯文本、富链接与首图。AI 复用结构化工具确认，加入任务管理页及下次执行提示。
4. 用临时库、假时钟、模拟 HTTP 与重启回归证明多目标、两类补齐、夏令时、并发领取、权限撤销与结果未知。使用实际账号核对文本、链接、正文、图片、主动与延后送达。真实送测只在得到目标授权后进行。增加绑定后重新生成 Wails 绑定并运行 Go 和前端相关检查。实施阶段提交前核对 CURRENT 和规格。
