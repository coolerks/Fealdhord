# 实施与整体验收计划

状态：实施中。一个 Trellis 总任务、一个整体交付结果。顺序用于管理模块依赖与局部测试，各可验证部分按项目约定本地提交。

| 顺序 | 工作 | 依赖与验证 |
| --- | --- | --- |
| 1 | 固化现有协议/历史 fixture，锁定合格的三个官方 SDK 版本。迁移三个适配器、配置高级项与接线。 | HTTP mock 验证 JSON、SSE、尾帧、思考强度、用量、取消、断流和网关扩展。真实服务至少验证截图所用协议的长回复。 |
| 2 | 接入模型资料解析、源优先级、ID 匹配、领域覆盖、价格/模态、离线索引、供应商图标与手动覆盖，在设置和聊天选择器显示。 | 依赖 1 的配置契约；对照 Models.dev 官方源码与实际样本、Pi 实际 JSON、本地缓存故障。验收冲突、前缀、原始 ID 保留、手动覆盖、零价、缺字段与离线。 |
| 3 | 接统一执行器、权限、审批与审计，完成 44 项工具与业务回归。 | 依赖 1 的工具事件。每项有 Schema、实际服务及权限断言；真实临时库验证订阅、分类、阅读状态和回滚；检查重复、冲突、取消、过期、外部结果未知。 |
| 4 | 实现上下文构建、预算、裁剪/压缩、持久恢复及面板。移除聊天的内联搜索行，接自然语言找文和独立选文。 | 依赖 2 的模型窗口、3 的工具/引用。中英混合、缺上限、大小窗切换、工具调用对、授权撤销与旧历史验证。 |
| 5 | Skills 管理、使用及安全导入，接入 MCP Client 的 stdio/HTTP、认证、目录、断线恢复。 | 依赖 3、4。验证 Skill hash 与权限交集，恶意目录不可调用，同名工具、取消、重连、权限变更与外部写不重放。 |
| 6 | 完成 MCP Server、独立本机外开关、HTTP/HTTPS、证书和客户端权限，接审计与审批。 | 依赖 3。用当前及兼容旧客户端验证协议协商；核对本机 HTTP/HTTPS、外部接入关闭/开启、授权局域网 HTTP、远程 HTTPS、无效证书和撤销。 |
| 7 | 整体验收，更新正式规格、绑定、设置示例与状态记录，在同一交付中涵盖上述所有能力。 | 完成 1–6，保留 mock、原生和实际供应商的不同证据，明确平台和配置限制。 |

## 检查与回滚

- 运行 gofmt、go test ./...、go vet ./...，对 AI/Chat/Runtime/MCP/相关数据包运行 go test -race；以临时 SQLite 库证明迁移、历史保留与恢复。回滚点为升级前快照及现有 SDK 回归 fixture。
- 运行 npm --prefix frontend run typecheck、npm --prefix frontend run lint、npm --prefix frontend test -- --maxWorkers=1、npm --prefix frontend run build。变更绑定后运行 wails3 task bindings，按现有方法验证原生开发构建。
- 最小整体验收串联真实模型找文并返回引用，审批后添加/归档订阅，切换小窗口模型后整理长上下文，重启离线检查图标和已保存覆盖，最后从另一个 MCP 客户端经 HTTP(S) 按同一权限调用和复核状态。真实服务与网络环境使用授权测试配置并记录方案，缺凭据或设备时保留待验证状态。
- 实施前检查最新版 PRD、44 项清单、SDK/协议证据和已确认远程接入规则；用户批准该方案后运行 task.py start。实现阶段在同一任务记录覆盖证据并同步 CURRENT 和 LATEST。
