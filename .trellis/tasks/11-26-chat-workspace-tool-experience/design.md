# 全局 AI 会话组织与工具体验设计

## 边界与联验

全局聊天保留现有侧栏、输入框、设置、Wails API 和模型运行器。三个子任务分别修改分组及目录授权、技能与用户消息、MCP 连接及运行限制。设计详见[分组](../11-26-chat-group-management/design.md)、[技能与输入](../11-26-skill-composer-experience/design.md)及[MCP 与预算](../11-26-chat-mcp-tool-budget/design.md)。

全部子任务顺序完成。分组和技能都会修改聊天数据及 `ChatDialog.tsx`，后续迁移使用届时的下一个版本号。MCP 任务在已有技能权限和引导处理基础上接入动态工具，保留计划模式已有的工具集切换。最终联验场景是在组内新建对话、选择技能、发送消息并按需连接 MCP，随后在设置恢复该组并重开消息。用临时数据库和模拟 MCP／模型完成，目录与凭据分别用临时目录和测试凭据库。

## 兼容及发布

- 旧分组和技能继续以原有默认图标显示，旧消息不补造技能标记。原有连接配置、单工具权限和会话归档数据照常读取。首次读取未设置的预算时应用新默认值。
- 迁移及生成绑定与对应子任务一同提交。应用文档只在实现和验证后更新交付状态。避免在生产库上试跑升级或连接真实用户的 MCP。
- 若需要回滚，在测试备份上验证恢复。数据库、技能元数据和 MCP 设置各自沿用现有持久化及备份边界。
