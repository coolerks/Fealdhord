# 长文翻译一期设计

## 1. 入口与处理顺序

沿用 `translation.API.Get`、`Translate`、`Cancel` 与 `translation:progress`。进入服务后依次固定当前正文来源和版本、匹配缓存、生成待翻单元、规划批次、串行请求、校验和保存。标题与摘要后台翻译继续走既有流程。阅读模式仍以实际原网页正文为准。

打开文章先显示已匹配正文版本的译文。如果全部待翻内容能装进一个常规批次，直接请求一次。大于一批时，交互路径先选择打开位置附近最多三个完整短块，无法定位时从正文开头选择。可由阅读器随首次翻译请求提供一个当前块 ID，后端按实际正文快照校验，过期或无效时回到正文开头。后台按正文顺序组批。首批提交后，剩余内容按原文顺序执行。标题无缓存时随首批发送。若起始段过大，首批可以同时带可完整翻译的邻近短段，长段保留原文直到可完整替换。

## 2. 分批与翻译单元

- 复用 `ai.ContextBudget(model.Metadata)` 和 `ai.EstimateRequest`，对组装完成的实际请求估算。首批正文目标约 350 个估算 tokens，最多 3 个原文块。常规批正文目标约 1,200 个估算 tokens，最多 10 个提交单元。两者是初始吞吐参数，均需通过真实请求的输入校验。
- 按目标语言的输出扩张为译文预留空间，并计算 JSON 及标记开销。输出预算起始可用 `max(256, ceil(正文估算 × 1.5) + JSON 和标题预留)`。输入上限和输出额度采用模型预算与翻译服务保守上限中的较低值。预计输出预算不够就拆批，模型上限未知时保留保守正文目标。提示和必要上下文已超限时明确返回预算错误。
- 标题、章节标题、现有用户提示和少量相邻文字提供有界上下文。相邻文字单独标明用途，返回仍按请求的单元 ID 对应。用相同术语要求覆盖同一任务的每批译文。
- 普通段落作为一项。超长段先按句界拆分，单句仍超限时沿安全文字边界细分。先解析已清洗 HTML 的文本及行内结构，再切分。行内代码保留原内容，链接目标及其他登记属性由本地恢复，允许翻译链接文字。切分时保留成对的行内标记、空白、Unicode 字符和原始顺序。
- 片段 ID 由原块位置、内容标识和片段序号确定。同次运行使用同一拆分计划。只有父块所需片段都有效时才合并和显示。父块保持原 ID，进度分母固定为源正文块数。

## 3. 结果保存与恢复

- 保留 `article_translations` 的现有主键与 `blocks_json` 完整译文格式。增量迁移为译文记录增加 `source_version` 和小型 `checkpoint_json`。检查点只保存未合并父块的已验证片段及拆分配置标识，父块合并后移除相关检查点。多个写入字段与状态一次提交。
- 订阅正文按现有文章内容版本识别。阅读模式用真实清洗后正文的内容摘要，含提取版本，持久化到 `reader_contents.source_version`。相同正文重新提取时保持相同版本，内容改动时产生新版本。旧行采用空默认值，在首次读写实际正文时确认版本。后台全文完成判断同步核对正文版本。
- 前端取得阅读来源版本，将其加入译文查询身份。快照与进度事件携带版本标识，有效的正文任务在同一版本内按运行标识及进度序号识别先后。后端写入前在短事务核对当前版本和取消状态。迟到结果不发布到新的阅读视图。
- 历史完整段落继续从旧 `blocks_json` 读取，按同来源、语言、段落内容以及可用标记校验后复用。旧完成记录待核实的部分通过当前正文重建覆盖，保留仍匹配的段落。新片段检查点还需匹配拆分规则及生成该片段时的模型与提示快照。失配时只重建该父块的片段。迁移升级测试验证旧译文可见和备份流程。

## 4. 错误与任务边界

| 条件 | 动作 |
| --- | --- |
| 返回对象完整，但个别项缺失、重复、清洗后为空或标记异常 | 独立校验并保存有效项。异常项形成更小批次，最多拆批补发一轮。 |
| 明确输出截断，或完整 JSON 无法解析 | 保留之前已落库结果。完整对象中能独立校验的项可保存。无法解析时缩小当前批次重试。 |
| 网络波动、超时或临时服务错误 | 对同批次短退避重试一次。每个提交单元最多两次额外请求。 |
| 有限重试仍失败 | 留下未完成块，继续处理后续独立批次。连续两个批次无任何有效结果则暂停，避免整篇重复消耗。 |
| 429、预算耗尽或模型配置错误 | 停止当前派发。后台沿用限流等待与预算机制，前台显示暂停原因。每次后台补发都计入既有预算。 |
| 取消、版本冲突 | 停止后续派发和过期写入，已提交译文和检查点可续翻。 |

完成依据为当前版本所有计划块均已有有效结果，以及任务需要的标题已就绪。图片、独立代码和仅格式节点继续按现有提取规则处理。保持同一文章、语言和来源只有一个执行，续翻入口继续使用现有 API。

## 5. 阅读器反馈

无完成块时显示「正在生成首批译文」。有结果后显示「已翻译 3/66 段」和取消操作。暂停或部分失败时保留已到达译文并显示「继续翻译」。显示模式选为仅原文时保持原文。进度按已提交的完整正文块计算。按块更新译文时保持阅读锚点，保留图片、目录和代码交互。

## 6. 采用的行业实践

DeepL 的分句、HTML 结构保留和上下文字段支持按块翻译设计。Azure Translator 的请求规模和项数限制支持双重分批约束。Google Cloud 批翻译的部分写出与取消机制支持检查点和续翻设计。memoQ 的精确与上下文匹配支持限制译文复用范围。起始 token 目标与重试次数是折栈的设计参数。
