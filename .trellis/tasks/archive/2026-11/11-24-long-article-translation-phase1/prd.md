# 长文翻译一期优化

## 目标

缩短长文从发起翻译到看到第一段正文译文的时间。长段或局部失败时，用户仍能继续阅读和翻译。沿用现有模型用途分配、阅读显示方式、订阅策略和按正文块存储的译文。

## 背景

截图中的 0/66 表示已有 66 个可翻译块，首批译文尚未提交。当前正文最多按 10 块与 1,800 个 HTML 字符串行发批，超长单块会绕过字符分批。首批必须完整响应并落库才显示。漏段后会保留有效译文，但会结束本次执行。现有依据见 `internal/translation/blocks.go:71`、`internal/translation/service.go:531`、`internal/translation/service.go:618` 和 `internal/translation/service.go:664`。

## 需求与验收

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| LT-1 | 长文先提供少量可读译文 | 可装入常规批次的短文一次完成。66 块长文在第一批正文译文提交后即能看到译文，余下批次继续串行。重开时优先显示已缓存段落。 |
| LT-2 | 分批适配模型输入与输出预算 | 实际请求估算包含提示词、正文、标题及 JSON 包装。每批符合配置后的输入、输出和块数上限，小上下文模型自动缩小批次。 |
| LT-3 | 超长段安全拆分并可续翻 | 超长段按句子或安全文本边界拆分，保留链接、强调与代码结构。片段全部通过才发布原段译文，进度只计一个原段。中断后只补缺失片段。 |
| LT-4 | 局部失败可恢复 | 漏段、重复 ID、空译文、截断和标记异常有有限的局部重试。有效译文及时保留，独立批次可继续。待补段保留原文及续翻入口。只有完整结果可标记完成。 |
| LT-5 | 译文与正文版本准确对应 | 取消、重启、变更目标语言及重新提取正文时，结果归属正确。原文相同可复用旧段，改动段和迟到结果不会污染当前正文。 |
| LT-6 | 保持阅读体验和既有策略 | 显示模式与翻译动作独立。译文更新保持阅读位置，保留标题、列表、表格、图片及代码语义。后台翻译保留现有真实全文来源和预算规则。 |

## 范围

本期保持同一文章、目标语言和来源的批次为 1 并发。每批仍等待结构化结果校验。前后台优先队列、批次并发、按滚动动态改派、实时逐 token 渲染、独立术语管理界面和新翻译平台放在后续评估。

## 效果验证

用相同原文、目标语言、模型及冷缓存对比新旧路径。测试覆盖短文、66 块长文、单段超长、HTML 内联标记、混合语言、存量库、限流和取消。记录首段可见时间、全文完成时间、模型请求数和输入输出 tokens。约定优先改善首段可见时间，完整性与缓存隔离是发布门槛。真实模型表现以实测记录为准。
