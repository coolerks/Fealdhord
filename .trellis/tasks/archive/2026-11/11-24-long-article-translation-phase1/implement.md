# 长文翻译一期实施计划

1. 审阅批准后激活任务。在主会话加载 `trellis-before-dev`。先用 66 块及超长单段固定样本记录现有串行请求数、首批可见时间和全文耗时。模拟模型用于控制等待、漏段及截断。
2. 后端先加纯分批逻辑，使用 Go 已有模型预算。覆盖短文单请求、较小首批、实际 JSON 估算、模型元数据较小、长句与 HTML 安全拆分。保留 `internal/translation/blocks.go` 的原文块身份，避免 DOM 身份依赖片段。
3. 在 `internal/translation/service.go` 调整批次执行和结果合并。继续串行，记录每个请求和每个有效结果。增加局部补发、错误分类和连续失败停止。回归断言原本有效的段落不会再次进入重试负载。
4. 在 `migrations/` 新增兼容迁移，在 `internal/database` 接入源版本、检查点、正文完结资格和事务写入校验。用实际 SQLite 验证升级、取消、重启、原站刷新后只复用仍匹配的段落、同步晚到结果丢弃。使用现有 sqlc 生成流程。涉及 DTO 时运行 `task bindings` 生成前端绑定。
5. 调整 `frontend/src/features/reader/` 的进度状态、目标版本隔离、暂存读到位置和继续入口。复用共享按钮。以假 Wails 事件验证旧任务事件丢弃、首批前后的提示、进度分母稳定、仅原文保持以及滚动锚点。
6. 跑 `go test ./...`、`go test -race ./internal/translation ./internal/database ./internal/reader`、`go vet ./...`。前端跑类型检查、lint、组件和全量测试以及生产构建。用相同模型配置对照同一批固定长短样本，记录分批数、首个正文块可见时间、全文完成时间、重试率、token 用量、缺段和标记校验结果。
7. 同步中文阅读规格、当前状态、交接和独立修改记录。明确区分模拟网关和真实模型结果。确认验证通过后按项目授权本地提交并归档。

## 风险与回退

- 首批较小在 66 块短段示例中可能多一次请求。若首批没有明显改善或请求开销升高，调大常规批预算或调整首批触发阈值，再对同一样本复测。
- 错误补发可能放大调用量。重试有单元上限，遇服务级错误暂停，后台预算覆盖每个尝试。
- 片段边界和版本切换是主要数据风险。先做结构、事务和旧缓存兼容验证，再接入阅读器。采用增量迁移，旧译文留在原表，回退无需删除数据。

## 实施结果

LT-1 至 LT-6 已实现。进度顺序复用严格递增的 `Record.updatedAt`，与 `sourceVersion` 一起隔离旧任务事件。Go 全量测试、相关竞态、vet，以及前端 206 项测试、类型检查、lint 和构建通过。变更和 66 段模拟对照见 `docs/08-handoffs/history/2026-11-24-long-article-translation-phase1.md`。真实模型和桌面实机待复测。
