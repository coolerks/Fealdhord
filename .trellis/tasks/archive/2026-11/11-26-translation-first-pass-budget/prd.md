# 正文翻译首轮预算和逐段回填

## 问题

实际抓包中，六段译文首轮的 294 个输出 token 全部用于推理，自动补译扩大到 588 才收到正文。长文也报告过 `finish=length` 和大量缺段。用户要求每个完整段落在流式输出期间独立回填。

## 验收

- 首轮按预计译文及模型输出上限留出额外余量，短文默认无需借助补译获得这部分预算。小输出窗口仍可用，长文按输入和含余量的输出约束串行分批。正文翻译优先使用模型已配置的低推理档位。
- 第一段及后续各段通过内容和格式校验即独立保存并通知阅读器。单个 SSE 增量带多条记录也逐条通知，完整 JSON 末段无需等换行或流结束。超长段按完整原文块更新。
- 截断和断流保留有效译文，补译只请求缺失项。复用 SQLite 检查点和阅读器现有事件，不改变正文、缓存或展示接口。
- 用可控模型流及临时数据库验证首轮预算、逐段提交和续译。通过用户授权的本地网关进行一次实际六段复测。
