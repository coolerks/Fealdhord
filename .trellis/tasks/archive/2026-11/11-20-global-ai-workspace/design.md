# 技术设计

## 工作区与会话

在应用 Shell 中按全局 Chat 目标切换两栏内容，侧栏复用窗口控件和尺寸体系，保留阅读状态及滚动锚点。全局会话视图与侧栏使用同一状态源和 Query 缓存。提取全局与原弹窗确实共用的会话读写、轮询、状态和文章选择逻辑，保持文章与分类入口现有行为。保留侧栏折叠及窄视图下的返回入口，隔离阅读区快捷键和焦点，返回时恢复进入前的阅读焦点。生成状态归后端所有，离开工作区不触发取消。

## 选模型与发送

复用 AI 设置的配置快照，筛选已启用且所属服务可用的模型，使用本地稳定模型记录 ID 作为值。默认分配用于首次预选，用户的选择作用于该工作区后续发送。在 `Chat.Send` 增加可选 `modelId`。全局请求携带该值时，后端核验会话范围，复用 `internal/aiconfig/service.go` 已有的启用模型、服务凭据及适配器解析路径。模型失效时返回可显示错误，避免静默换用其他模型。省略该字段时沿用当前聊天分配，文章和分类调用可直接兼容。发送时确定适配器及模型显示名，随后保持当前请求及已存消息的模型记录。无需改动会话或消息表。

## Markdown 和设置

模型回复按不可信文本处理。使用维护中的 Markdown 解析器输出受控 React 节点，禁用原始 HTML 与远程媒体节点。链接仅接受明确允许的外部协议，通过现有桌面接口打开。代码块复用项目的 highlight.js、代码主题目录和复制交互，主题规则以渲染区域为作用域，避免文章和聊天互相覆盖。流式回复的解析与高亮需遵循现有消息预算，已有消息保持原始文本存储。

新增 `chat_code_theme`，通过现有 SettingsService 读写和校验，在 AI 设置展示对应 SearchableSelect。复用主题目录与安全标识校验，旧记录缺字段时回退 `app`。在 Go DTO 修改后生成 Wails 绑定。SQLite 的偏好 JSON 可以兼容新增字段。

## 风险与回滚

留意离开或切换会话时的进行中请求、模型被停用时的失败反馈、不同主题 CSS 的隔离及流式 Markdown 未闭合块。逐阶段保持旧文章调用可用。若撤回工作区提交，原全局弹窗可继续读取相同的会话和消息。
