# Skill 渐进式披露、会话分组与本地工具设计

## 接入位置

在 `internal/chat` 和 SQLite 实现分组归属、目录来源和会话提示词，在 `internal/appagent` 实现受管 Skill 存储和本地工具。沿用 `Platform.RunTools` 给全局对话提供工具和说明，沿用 `internal/agentrun` 的模型调用及循环。复用桌面原生选择器、AI 侧栏、Skill 设置、工具权限和两种审批界面。四个本地工具通过独立的本地会话注册入口添加，MCP 服务端继续使用可公开的工具清单。

同一个 Trellis 任务按分组与目录、安装、按需读取和本地操作四个阶段验收。会话目录和提示词为文件工具提供同一份后端来源，Skill 安装与读取共享同一版 Skill 目录。

## G1 分组、归属和侧栏

1. 新增会话分组与有序文件夹记录。全局会话增加可空的分组 ID，升级后的已有会话默认无分组。新建分组流程在事务中保存名称和目录顺序。目录由原生选择器提供，后台确认是有效目录并按平台归一化去重；取消继续保留对话框草稿。允许重复打开选择器添加多个文件夹。
2. 会话从组内入口发出首条消息时，以分组 ID 创建已有 `global` 类型的会话。沿用原有普通新对话入口和创建时机。分支复制组归属，归档恢复和历史读取保留它。现有文章和分类会话维持原有 scope。数据库查询从持久化归属获取目录，客户端发送时无需再传绝对路径。
3. 普通会话和各分组分别查询。组内可复用已有按置顶、活动时间排序的行为，沿用各列表的最近条数边界。折叠的分组按需加载列表，已打开会话可继续读取、发送和显示标题。
4. 在现有 AI 侧栏的「会话」上方加「分组」。分组头有「新建分组」，组行可展开、收起，并通过独立的「组内新对话」按钮进入草稿。两段及每个组的折叠状态各自存放在桌面工作区前端状态中，切换工作区保留本次运行状态。折叠区域退出键盘导航。使用共享 shadcn 组件，校验可访问名称、焦点返回和禁用态。

## G2 目录推导和工具授权

1. 普通会话目标 `~/.Fealdhord/会话文件/YYYY-MM-DD/会话ID` 用 Go `os.UserHomeDir` 解析实际主目录。新会话在创建时保存设备本地日期。为旧全局会话从原创建时间回填并固定日期。组内分支生成新的会话 ID 和创建日，仍使用原分组。未绑定目录的分组按普通会话规则处理。
2. `chat.Service.Send` 在构建模型请求时生成当前会话目录上下文，记录有序的授权目录与默认工作目录，再传入工具运行。系统提示词以结构化数据字段展示当前分组实际绝对路径，或展示普通会话的绝对输出目录及按需创建规则。文件名、路径及分组名称按数据编码，工具启停仍沿用会话权限。只传当前会话需要的路径，不预读文件或把路径扩散到会话摘要及审计。
3. 多个分组目录时，相对路径和省略的 `workdir` 以第一个可用目录为起点，提供其他目录的绝对路径供模型选择。发送和工具调用间目录不可用时报告该路径不可用。拥有分组目录的会话继续以该组范围为准，目录全部失效时显式报错。
4. 普通会话通过一个按需授权的子目录访问文件。建立会话、发送普通消息、获取提示及只读操作均不修改文件系统。`write` 收到用户要求并通过工具审批后，从可信已存在祖先顺序校验、创建必要父目录；授权只覆盖完整会话子树，阻止路径穿越、祖先链接替换和兄弟会话读取。`read`、`edit` 遇到未建立的目录正常返回未找到。
5. 普通会话省略 `shell.workdir` 时优先在已存在的会话目录启动。目录还不存在时可从系统临时目录启动，经审批展示真实起点，提示词仍要求输出使用该会话绝对目录。明确指定不存在的工作目录会返回错误。仅启动命令前的解析与审批均不会创建目录，用户批准的命令本身可创建文件。

## S1 导入、安装与存量迁移

1. 使用原生文件选择器选择 ZIP 或 `SKILL.md`。Go 先验证归档项和声明文件，再以流式 I/O 暂存到应用数据目录。ZIP 支持根目录或单层根目录的单个 `SKILL.md`。目录内的常规文件按相对路径保存原始字节。BOM 和换行兼容继续由声明解析处理；预览未编辑的文件保持其原始字节。
2. 首期压缩包上限 64 MiB，解包总量 256 MiB，单个常规文件 64 MiB，归档项最多 2,048 个，包内相对路径最多 16 层。`SKILL.md` 沿用 256 KiB 上限。先检查声明尺寸，再按实际读取字节执行每项和总量限制。禁止绝对路径、越界、软链接、特殊文件及平台不接受的路径，提前发现重复、大小写等价路径和文件与目录冲突。每项与总量限制都有独立错误提示。
3. 预览返回一次性导入 ID、说明 Markdown、名称、描述和文件清单，清单包含相对路径、大小。前端仅回传导入 ID、用户编辑过的声明和启用状态。提交时重新校验，更新目标采用版本检查。取消、过期、关机中断或提交失败时清理暂存；现有版本继续可用。
4. 受管安装目录每版独立。文件全部落地后才切换当前版本元数据，导入、编辑、启停和删除同名 Skill 串行。旧版本保留至进行中的读取与命令结束。崩溃恢复清理本功能登记的暂存和未发布版本。设置列表只读取元数据，编辑时单独加载说明和清单。
5. 存量 `skills/<name>.json` 在升级后仍可读。将已验证的 Markdown、启用状态、工具声明及参考资源迁入受管目录，成功登记新版后优先使用新版。迁移失败时继续读取旧记录，旧数据保留以支持回滚。删除时处理存量记录，避免被重新发现。

## S2 渐进式披露与会话权限

1. 初始模型请求仅包含可用 Skill 的名称、描述及逻辑入口 `skill://<name>/SKILL.md`，手动选中的 Skill 在目录里被标明并优先读取。目录按模型预算控制大小，显式选择优先保留，停用的 Skill 不进入目录。
2. 模型调用 `read` 读取入口后才激活，随后用同一逻辑路径访问资源。返回的资源内容作为工具数据处理。会话工具禁用时，保持无工具，不向模型提供可调用的 Skill 入口。用户显式选中 Skill 时可按现有会话行为提供其预算内的说明，参考资料仍按需读取。
3. 读取 Skill 文件和读工作区共用 `read`。路由为 Skill 时仅访问本轮可用的版本，检查启停与权限。工作区访问按 G2 解析，安装目录只开放给文件工具读取。`allowed-tools` 与旧 `tools` 只缩小原有授权。继续执行显式选择 Skill 的工具交集。模型自动激活后，在调用实际工具前应用同一规则。读取当前 Skill 入口及资料仅授权该 Skill 范围。
4. 工具声明和运行权限在 `Platform.RunTools` 与 Runtime 调用边界校验。用同一套逻辑覆盖普通模式和工具目录压缩模式。大模型上下文裁剪优先保留当前已激活的说明和最近资料页，旧页可重新读取。正文、资源及审批参数不作为新授权来源。
5. 读取函数接受模型本轮预算，结果始终符合工具硬上限。通过明确的每工具结果策略让 `read` 使用自身行号续读，现有 12 KiB 通用分页继续用于原有工具。小上下文模型可得到更短页与续读位置。禁止日志、审批历史与工具审计为了记录结果而额外保存完整包、工作区原文或命令输出。

## T1 至 T3 文件工具

文件操作沿用 G2 的分组或普通会话目录来源。相对路径从默认目录解析，绝对路径须在本轮某一授权根下。通过 Go 的 `os.Root` 等实际访问约束处理路径和符号链接，访问前后确认目标是常规文件或允许的目录。已安装 Skill 的文件工具授权为只读。

| 工具 | 输入 | 输出与失败语义 |
| --- | --- | --- |
| `read` | `path`，可选 `offset`（从 1 开始）、`limit` 和 `lineByteOffset`（长行续读时使用） | 返回带行号文本、已读范围、是否截断和下次位置。最多 2,000 行且序列化结果最多 50 KiB。达到字节限额时在合法字符边界停下。单行超限时注明行内截断并提供继续读取该行的 UTF-8 字节偏移。内容识别为二进制时返回跳过状态，无正文。目录由 `shell` 枚举。 |
| `write` | `path`、`content` | 创建缺失父目录，创建或覆盖整个文本文件。返回成功路径与字节数。先在同目录暂存，再按当前平台的替换语义提交，失败时保留旧内容。 |
| `edit` | `path`、`oldText`、`newText`，可选 `replaceAll` | 精确替换，返回替换次数。默认必须有一处匹配，缺失或歧义返回可修正错误。拒绝空旧文本及二进制。保留未替换内容及现有换行风格。 |

`read` 用字节特征识别文件类型。支持 UTF-8、带 BOM 的 UTF-8 及带 BOM 的 UTF-16；根据编码有效性、NUL、控制字符及已知二进制签名判断。扫描文件开头并校验准备返回的内容，偏移按解码后的行计算。无后缀文件走相同路径。两项写工具沿用现有参数尺寸和工具权限。写入或替换前保存观察到的文件身份，提交前核对并处理并发修改，避免静默覆盖审批等待期间的变更。

## T4 命令工具

- `shell(command, workdir?, timeoutMs?)`。工作目录可以是当前会话目录、其子目录或当前可访问的 Skill 目录。省略时按 G2 选择实际目录。工具通过参数传递实际工作目录，命令不拼接路径。用户可以用同一工具列目录、搜索项目或运行包内脚本。
- JSON 参数解析、有效目录确认、完整命令与目录展示、单次批准、再次校验取消与目录身份、创建进程按此顺序进行。审批对象绑定原始命令和已解析目录。两种 UI 共用现有审批入口和「允许本次调用」操作，内容以可滚动纯文本展示。
- 会话拒绝模式和自定义拒绝直接结束；其他模式均要求本次确认，通用「绕过审批」不能替代 `shell` 本次确认。技能声明无法代替用户批准，远程 MCP 不提供主机命令入口。模型端只收到执行结果。
- macOS／Linux 以本机 shell 执行，Windows 以系统 PowerShell 执行，均以当前桌面用户身份启动。命令继承该用户的系统权限，选择的工作目录只决定启动位置。进程使用有限环境并保持必要的 PATH、临时目录、编码或系统目录变量。凭据配置和模型连接环境不主动传入。该约束适用于应用启动的进程环境，主机进程仍可读取当前用户原本能读到的数据。
- 首期只执行前台命令。默认 120 秒，单次最多 300 秒，超时或取消后回收前台进程组或 Windows Job Object 内的进程。限制输出缓冲区，返回 `exitCode`、`stdout`、`stderr`、`truncated` 与超时状态。非零退出是命令结果。宣布已启动的命令超时或取消后说明执行状态，禁止自动重放。跳出前台进程组的独立守护进程不在首期保证范围。
