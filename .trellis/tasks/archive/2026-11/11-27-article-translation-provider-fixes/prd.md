# 修复多引擎文章翻译

## 目标

修复提交 `2d4713f` 的八项审查缺陷。有效的厂商响应能生成译文，失败结果可继续处理，已配置的凭据和已保存的翻译进度在编辑、重试和取消时保持一致。

## 需求与验收

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| TR-01 · P1 | 正确读取阿里云批量与通用翻译的官方成功响应。审查中模拟数字 `Code: 200` 时，两条路径都报协议错误。位置 `internal/translation/provider_alibaba.go:189,227`。 | 两条路径的本地 HTTP fixture 使用数字顶层状态码，分别成功返回译文。批量条目继续按官方字段映射到原文序号。 |
| TR-02 · P1 | 密钥只用于配置时确认的 HTTPS 来源。保存和草稿测试目前允许向新来源发送旧密钥，也接受 HTTP。位置 `internal/translation/config.go:160,224`。 | HTTP 输入和旧 HTTP 配置都不能触发请求。跨来源改地址时保留旧密钥的操作失败，重新输入密钥后才可发送。禁止跨来源或降级跳转转发。数据库保存失败后，原设置和原凭据仍可用。 |
| TR-03 · P1 | 标题与摘要仅在所需输入均成功翻译时记为完成。审查复现了摘要限流后保存空译文并返回成功。位置 `internal/translation/summary_api.go:62`、`internal/database/translation.go:130`。 | 局部失败返回对应错误，也可重试。已被误标完成的机器翻译缓存若缺少原文有内容的字段，可由正常读取或后台候选识别并补译。 |
| TR-04 · P2 | 机器翻译正文应保存已接受的长段片段，并确保行内代码与链接完整。审查复现了重发已成功片段，以及丢失代码后仍计为完成。位置 `internal/translation/body_api.go:376,398`。 | 长段尾片失败后，重启服务继续时只发缺片。带代码与链接的超长段合并后保留原有标记。返回缺失、重复或错误顺序的结构标记时不计为完成，已有缺标记译文可以修复。 |
| TR-05 · P2 | 百度单段补译使用与原始请求相同的速率限制。模拟标准版首次补译距原请求不到 1 毫秒。位置 `internal/translation/body_api.go:461`、`internal/translation/provider_baidu.go:158`。 | 标准版的原批次和补译按同一额度排队。取消等待不会发出后续请求。 |
| TR-06 · P2 | 恢复未配置 AI 翻译模型时的设置跳转，并为机器翻译提供对应入口。改文案后两个按钮消失，已有组件测试失败。位置 `frontend/src/lib/translation-api.ts:89`、`frontend/src/features/reader/Reader.tsx:255`。 | AI 模型未配置时可直接打开模型设置或文章 AI 设置，机器翻译缺配置时可直接打开文章 AI 设置。入口由错误代码和选中引擎决定。 |
| TR-07 · P2 | 取消期间清除译文后，旧任务不能重建记录。审查中清除后一条 `failed` 记录被重新写入。位置 `internal/translation/body_api.go:426`、`internal/translation/service.go:307`。 | 取消保留最后一次成功提交的结果。清除时即使请求晚到，旧任务也不能重建记录或再次发布被清除的结果。清除指定文章的全部目标语言时，取消范围一致。 |
| TR-08 · P2 | 当前文章的语言不受支持时，后台应继续处理其他文章。当前全局退避结束后会再次选中同一篇。位置 `internal/translation/worker.go:49`、`internal/database/translation.go:139`。 | 最新一篇因语种不支持被延后，下一轮能处理其他合格文章。认证、配置错误和厂商限流继续按全局规则退避。 |

## 范围

涵盖现有引擎及现有阅读器与设置入口。验证使用本地模拟厂商和临时数据库。真实厂商凭据联调、桌面实机验收、新增引擎及发布不在本轮范围内。
