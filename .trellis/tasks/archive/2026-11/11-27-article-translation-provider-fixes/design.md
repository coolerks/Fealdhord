# 技术设计

## 厂商协议与凭据

阿里云按官方响应类型解码两个操作，批量条目状态码与顶层状态码分别处理。使用厂商格式构造本地响应测试。

保存与草稿测试共用后端 URL 校验。空地址映射为厂商默认来源，比较 HTTPS 主机与有效端口。改变来源需为新地址明确提供密钥，或显式清除旧密钥。已有 HTTP 地址可在设置中读回并修正，运行时拒绝连接。生产 HTTP 客户端拦截跨来源和降级重定向。凭据旋转采用现有 AI 服务的模式，先写新引用，再保存配置，失败时清理新引用，配置生效后才清理旧引用。对配置和凭据的联合读写进行同步。

## 翻译写入与恢复

摘要对必需字段逐项校验，保留服务明确返回的错误。摘要与正文分别沿用文章来源版本校验。后台候选与缓存读取识别旧版漏译字段，区分只有标题可复用的情况。

正文复用已有 `checkpoint_json`。检查点匹配原文哈希、引擎与分片计划，通过校验的片段按批次保存。长段用带结构的切分机制，代码单元和链接属性在本地恢复。跨片段重组保留原有边界，校验失败的译段继续待译。读取旧缓存时仅撤销受影响段落的完成状态，并复用仍可校验的内容。

取消沿用正文已有的「最后已提交快照」语义。清除与旧任务的状态发布协调，写入不能脱离已取消的任务上下文。限流涵盖实际外部请求，百度补译继承原任务的频率配置和取消信号。后台将语种不支持归为文章级失败，复用已有延后机制。

## 阅读器与兼容性

阅读器保留结构化错误码，由错误码和设置中选中的翻译方式选择入口。凭据验证失败时设置显示具体修正动作。沿用现有数据库结构、Wails 方法和共享 UI 组件。升级后已配置的 HTTP 自定义地址需要改为 HTTPS 才能恢复连接。
