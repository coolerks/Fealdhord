# 文章翻译修复实施计划

1. 审阅确认后激活任务，在主会话读取 Reader、文章 AI、数据库与前端组件和 Hook 规范。
2. 修改 `internal/translation/service.go` 与 `internal/database/translation.go`，同步增加现有 Go 测试中的针对性回归。先核对错标缓存、同语种旧记录、已翻订阅正文、提取失败及成功提取后的调度。
3. 修改阅读器翻译 Hook、工具栏、正文显示和文章 AI 设置，复用共享控件。覆盖键盘选择、显示切换的零模型调用、单源覆盖逻辑、标题与正文状态的区别，以及图文段落与表格、列表的显示。
4. 执行 Go 格式化、翻译／数据库／Reader 相关测试与竞态检查，以及 `go vet ./...`。执行前端类型检查、lint、组件测试和生产构建。按结果补齐受影响范围。
5. 更新中文规格、状态、交接和独立修改记录，记录实跑结果。检查文件范围和 diff，再按项目已有授权提交本次文件。归档 Trellis 任务。

风险集中在现有翻译缓存、后台队列资格与阅读器 DOM 的还原。先用临时数据库和模拟模型复现，再用真实组件测试验证 DOM。回退采用正常 Git 反向提交，保留用户已有译文。

## 实施结果

TR-1 至 TR-6 已实现。Go 全量测试、vet、相关竞态检查，前端类型检查、lint、生产构建及限制并发后的 205 项全量测试通过。详细行为和验证见 `docs/08-handoffs/history/2026-11-24-article-translation-fixes.md`。
