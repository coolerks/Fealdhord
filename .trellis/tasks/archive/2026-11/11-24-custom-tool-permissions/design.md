# 技术设计

## 设置与持久化

- 复用 `approvalModes` 和共享 `SearchableSelect`，补充 `custom` 值与菜单图标。所选值继续经过 `chat_approval_mode`、会话临时选择和 `SendInput.ApprovalMode`。既有偏好默认仍为 `ask`，已保存值照常读取。
- 在「MCP 与权限」增加「工具权限」区。工具目录按名称、显示名称和连接搜索，规则用共享选择器。保存失败保留已保存值并提示重试。使用桌面 Wails 绑定提供设置查询和逐项保存入口，公开 MCP 工具目录及外部客户端授权仍由现有接口提供。
- 规则持久化在现有 AI 平台配置目录，复用有界校验及原子 JSON 写入。设置存储缺失表示没有显式规则。逐项保存串行读取和更新，保留其他工具的配置。读取损坏时返回安全错误，避免把已配置的拒绝规则当成空规则。
- 内置工具按稳定注册名匹配。外部工具按连接、连接目标指纹、工具类别和原始工具名匹配，使用无歧义编码。连接目标指纹由连接目标配置生成，凭据仅用于现有连接过程。目录列出已发现工具，并允许清除已经配置但暂时不可用的规则。

## 执行与边界

- 发送时确定当前会话模式。自定义模式使用当轮已保存的规则快照，从共同工具执行入口决定确认、拒绝或放行。已经发出的回复沿用该快照；配置修改从下一条消息生效。
- 内置和外部工具共用同一个审批判定。未配置的工具使用注册默认值。拒绝返回已有的权限错误和审计状态。精简工具目录调用原工具执行器，规则随原始工具身份判定。
- 对聊天单独装配的 `read_article`，复用同一规则判定和确认入口。权限设置与当轮文章 ID 授权同时满足才可读取正文。外部连接的资源和提示词工具沿用同一执行入口，并使用区分工具类别的独立规则。
- 审批规则只应用于全局聊天自定义模式。外部客户端的工具授权、数据范围及服务端审批决策由现有调用链处理。技能筛选、显式数据授权、参数校验和取消语义均复用既有路径。

## 回滚

可以移除新入口并由旧版本按既有兜底读取审批偏好。独立规则文件不参与旧版本工具执行，也不改变聊天和模型数据结构。
