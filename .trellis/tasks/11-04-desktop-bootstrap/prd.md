# Phase 0：桌面工程与基础调用链

## 目标与用户价值

将已评审的整体规格推进为可构建、可启动的桌面工程，为正式阅读界面提供可靠的前后端调用基础。

## 已确认事实

用户在完整规划摘要后明确要求“建立任务，开始规划任务，并开始实施”，批准执行此前实施计划。本任务只是已展示 Phase 0 的可验收拆分，不扩大范围。仓库无应用代码，Wails v3.0.0 和 Go／Node 本机可用；doctor 在受限环境中失败；文档中文、禁止子代理。

## 需求

- BOOT-01：固定工具链与依赖，采用官方 React TypeScript 模板建立工程，保留已有文档与配置。
- BOOT-02：Go 应用装配、具体 DTO 和生成绑定，UI 能实际获取应用信息。
- BOOT-03：有界诊断操作通过 Go context 支持启动、事件、快照与取消，窗口卸载清订阅。
- BOOT-04：真实 native 构建与本机窗口启动验证，记录环境检查结果。
- BOOT-05：提供可复现开发／测试／构建命令、仓库忽略规则与交接。

## 验收标准

AC-B01：Go test／vet、前端 typecheck／lint／test／build 通过，绑定生成可重复。
AC-B02：本机真实 Wails 窗口完成获取信息、开始诊断、接收进度、取消并看到终态；不是浏览器 Mock。
AC-B03：运行中重复开始、重复取消、取消后旧事件、服务关闭和并发访问受测；诊断不会访问网络或付费服务。
AC-B04：工具链、doctor、启动和测试证据写入中文文档，其他平台保留未测。

## 范围外

本任务不实现 RSS／数据库／AI／完整 Shell、不改变全局工具链、不发布。Phase 1 跟进正式玻璃与双视图，沿用既有规划。

## 规划批准

采用上一轮 design.md／implement.md 已展示的 Phase 0 方案，用户本条消息授权实施；本拆分无新增产品决策。
